# Voice Session WebSocket

Generated by `tools/generate_api_docs.py`. Do not edit by hand.

> Authenticated session channel initiated by the device. The channel does not
> just carry binary audio payloads — it also carries lifecycle events,
> wake-word metadata, and other control messages exchanged during a voice session.

- Endpoint: `configured by local-control voice/set_config`
- Transport: `device-initiated WebSocket`
- Auth algorithm: `hmac-sha256-v1`
- Server proof message: `server:<device_id>:<client_id>:<device_nonce>:<server_nonce>`
- Device proof message: `device:<device_id>:<client_id>:<device_nonce>:<server_nonce>`

The device opens this WebSocket after a wake trigger, a remote wake
monitor request, or an explicit voice start request. This is not the permanent robot control
channel; local-control RPC remains the source of truth for settings,
pairing, and durable robot control.

## Message Index

- `auth_begin`: Device starts voice WebSocket mutual authentication.
- `auth_challenge`: Server proves it knows the voice token and sends a server nonce.
- `auth_verify`: Device proves it knows the voice token for the same nonce pair.
- `auth_ok`: Server accepts voice authentication.
- `device_hello`: Device advertises voice transport and microphone audio format.
- `server_hello`: Server creates the voice session and advertises playback audio parameters.
- `listen.start`: Device starts a listening window.
- `listen.stop`: Device stops the current listening window.
- `listen.detect`: A peer reports the detected wake phrase for the current session.
- `tts.start`: Server starts TTS playback on the device.
- `tts.sentence`: Server streams one assistant sentence for subtitle display.
- `tts.stop`: Server ends TTS playback on the device.
- `stt.transcript`: Server sends the recognized user transcript for subtitle display.
- `ui.emotion`: Server requests a UI emotion change on the device display.
- `ui.alert`: Server requests a UI alert banner, message, and emotion.
- `ui.custom`: Server sends a custom UI payload for firmware-defined rendering.
- `system.reboot`: Server requests an immediate device reboot.
- `mcp.message`: JSON-RPC MCP envelope carried over the voice session.

## Binary Frames

- `device_to_server`: Opus audio frames from the device microphone after authentication and server hello.
- `server_to_device`: Binary audio frames for device playback after authentication and server hello.
